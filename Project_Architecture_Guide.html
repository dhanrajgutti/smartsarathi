Smart Saarthi

RTO & Police Vehicle Management System - Architecture Guide

1. Project Overview

Smart Saarthi is a comprehensive vehicle compliance and enforcement platform designed for RTO officers, PUC centers, Insurance agencies, and Traffic Police. It centralizes vehicle data, compliance tracking (PUC/Insurance), and violation management.

2. Technology Stack

Java 11+ (Backend) Oracle XE 11g/19c (Database) HTML5 / CSS3 / JavaScript (Frontend) WebRTC (Camera Integration) JDBC (Database Connectivity) Native Java HTTPServer

3. System Architecture

The system follows a Client-Server Architecture with a clear separation of concerns:

  • Frontend: Pure HTML/JS/CSS served as static files. Communicates with the backend via RESTful JSON APIs.
  • Backend: A high-performance Java server using com.sun.net.httpserver. It handles authentication, business logic, and database operations.
  • Data Access Layer (DAO): A dedicated layer using JDBC to interact with Oracle DB. Each module (User, Vehicle, PUC, Insurance, Challan) has its own DAO class.

4. API Documentation

Authentication

POST /api/auth/login

Authenticates users (Admin, Police, PUC Center, Insurance Agent) or Citizens (using Vehicle No + Chassis).

Vehicle Management

GET /api/vehicle/lookup?vehicleNo=...

Fetches full vehicle details, owner info, and real-time compliance status.

Compliance Modules

POST /api/puc/issue

Issues a new PUC certificate. Logic: Strictly blocked if pending challans exist.

POST /api/insurance/policy

Registers a new insurance policy. Logic: Strictly blocked if pending challans exist.

Enforcement (Police)

POST /api/challan

Issues a traffic violation challan. Captures GPS coordinates and server-side timestamp.

5. Key Algorithms & Logic

A. Compliance Blocking Algorithm

Goal: Ensure service denial for non-compliant vehicles.

  1. On PUC/Insurance request, system queries CHALLAN table.
  2. If payment_status = 'Unpaid', the transaction is aborted.
  3. Frontend displays a modal with specific challan counts and total fine amount.

B. Renewal Reminder Logic

Goal: Proactive notification for expiring certificates.

  • Query: SELECT ... WHERE valid_upto BETWEEN CURRENT_DATE AND CURRENT_DATE + 30
  • Algorithm: Uses CEIL(valid_upto - CURRENT_DATE) to calculate precise countdown days.
  • Channel: Supports multi-channel reminders (Email simulation implemented).

C. ANPR (Automatic Number Plate Recognition)

Goal: Extract vehicle numbers from live camera feed.

  1. Captures frame from video element using canvas.toDataURL().
  2. Sends Base64 image to backend (Future: Tesseract/OCR integration).
  3. Current implementation uses a high-reliability manual fallback for 100% accuracy.

6. Database Schema

  • USERS: Stores credentials, roles, and center assignments.
  • VEHICLE: Central registry for all vehicle specs and compliance flags.
  • OWNER: Contact information for automated notifications.
  • PUC_CERTIFICATE: History of all emission tests.
  • INSURANCE_POLICY: Registry of active and expired policies.
  • CHALLAN: Records of violations, fines, and payment statuses.
